# Documentation Index

## Purpose
This directory stores module-specific technical documentation for `com.etendoerp.go`.

## Documents
- `neo-headless.md` — Neo Headless overview and architecture notes.
- `neo-headless-guide.md` — detailed Neo Headless development guide.
- `onboarding-sampledata-packaging.md` — how onboarding sampledata is staged into `WebContent/WEB-INF/classes` for WAR packaging.
- `package-architecture.md` — current Java package boundaries, selector policy split, OAuth2 support split, and PR-scoped Sonar workflow.
- `onboarding-flow.md` — the `ensureOnboardingDataset` step pipeline (dataset, accounting chart/name wiring, GL Item provisioning, entity posting-account provisioning, periodControl (every period never-opened, ETP-5577), periodNormalize, sequences, orgReady, fiscal, orgInfo, customer, bankConnectionSync, bpGroupAcctPatch, acctdimVisibility, baseline), service responsibilities, included-tables rationale, NDJSON event format, the pre-provisioned tenant pool (ETP-5389: flag, `ETGO_TENANT_POOL`, filler process, claim, placeholder gaps), the initial period state per tenant type, and the accounting calendar review endpoints (`/sws/go/onboarding/calendar-review`, ETP-5577).
- `transactional-email-contracts.md` — runtime endpoint, executor/provider boundary, and server-side provider configuration for transactional email contracts.
- `document-email-contract-implementation.md` — step-by-step Java guide for adding document-send transactional email contracts.
- `aeat-303-submit-endpoint.md` — `POST /neo/fiscal303/submit` contract (AEAT Modelo 303 electronic submission, ETP-4456 Phase 2): request/response shapes, error codes, the idempotency guard, certificate flow, and known gaps.
- `STORED-COMPUTED-COLUMNS.md` — functional + technical guide to the stored computed column engine (EPL-1807): concepts, refresh modes, end-to-end flow, configuration, Oracle support, operations, and build validation. Illustrated with the `com.etendoerp.storedcomputedcolumn` pilot.
- `COLUMNAS-COMPUTADAS-ALMACENADAS.md` — Spanish version of the stored computed columns guide.
- `test-jvm-isolation.md` — why `OBBaseTest` subclasses run in their own JVM (`goIsolatedDalTest`), how to add a new one, and the unidentified pool leak behind it.
- `gradle-worktree-testing.md` — why `./gradlew test` from the Etendo root never sees a `git worktree` branch's own content, the `tasks.gradle` task-name collision this can cause, and the detach/remove/restore workaround to actually run Gradle against a worktree's code.
- `feature-flags-and-tenant-upgrade.md` — OpenFeature flag stack (local configuration or ConfigCat behind one swap point) and the backend flags it serves — including the `environment-access-enforcement-off` kill switch (ETP-5047) and the operator page for commercial access enforcement (deploy order, switching it off, what support sees for a blocked tenant) — the unconditional paid-environment paywall contract, and the tenant plan marker. The `tenant-upgrade` flag was retired in ETP-4966.
- Checkout and billing audit tables (ETP-5045) — `ETGO_CHECKOUT_REQUEST` (`CheckoutRequestStore`) and `ETGO_BILLING_EVENT` (`BillingEventStore`, the durable webhook idempotency gate) are described in the "Closed by ETP-5045" note of `feature-flags-and-tenant-upgrade.md`; both are readable from the read-only Classic windows **Checkout Request** (with its **Billing Event** child tab) and **Billing Event**. The local replay procedure lives in the functional repo (`schema_forge/docs/stripe-local-testing.md`).
- `open-and-notable-topics.md` — **the living register for the whole recurring-billing block (ETP-5045…5053)**: decisions still owed (the `activeUsers` flow-versus-stock problem), deployment constraints that are invisible in the code (the legacy price fallback and how the first priced plan retires it; the subscription-model switch `ETGO_SubscriptionModel`, OFF until the operator sets it after the deploy and then runs the opt-in R37 — switch first, decided 2026-10-14; JDK 17 for `gradle test`), how legacy plans and the per-tenant retirement of `ETGO_TenantPlan` work, and the traps worth not rediscovering (`VISIBLEAT_CLIENT_ID` scoping, the R31/R32 ordering invariant and its fiscal-compliance stake, the data-fix watermark that silently skips a late-dated fix), the subscription-row lifecycle and the single environment-access check with its 402 body (ETP-5047, §3.7–§3.11), plus what is handed forward — including the quota-definition gaps ETP-5051 inherits (periodless rows, now only R37 backfills, pre-ETP-5047 rows and new rows whose post-onboarding Stripe period read failed; stock-versus-flow aggregation; the `CONSUMPTION_SOURCE` meaning) and the missing per-period usage history that overage billing will need (§5.5–§5.12). Read it before deploying or before writing a data-fix that touches the tenant plan.
- Plan catalog and tenant subscription (ETP-5046) — `plans/2026-09-18-etp-5046-plan-and-subscription-design.md` is the design of record for `ETGO_PLAN`, `ETGO_PLAN_QUOTA` and `ETGO_SUBSCRIPTION`, the editable **Plans** window (with its **Quotas** child tab) and the read-only **Subscriptions** window. Read it before editing a plan's price: **re-pricing a plan does not re-price existing subscribers**, by design, on both the Stripe side and the Etendo side. It also records the two invariants that look like bugs and are not — a plan with zero quota rows is *unlimited*, and `STRIPE_SUBSCRIPTION_ID` is deliberately not unique. §6.1 defines the legacy price fallback (`etendo.go.checkout.price.id` keeps selling until the first priced plan exists) and §6.2 is the operator go-live checklist. The AD authoring record is `plans/2026-09-18-etp-5046-stage-b-ad-handoff.md`.
- `mcp-usage-telemetry.md` — the `ETGO_MCP_USAGE` table and the fire-and-forget writer behind it (Track B1): why the write is out of the business transaction, why it records shape and never content, the minted `Mcp-Session-Id`, and the per-instance opt-out.
- `hubspot-sync.md` — the HubSpot sync (ETP-5847): the five account lifecycle events (account created, demo ready, first entry, paid, trial expired) and the Stripe billing events (payment, failed charge, cancellation scheduled, withdrawn or done, one deal per productive environment) reported to the CRM through `ETGO_HUBSPOT_OUTBOX` and the *HubSpot Sync* process; configuration (`ETGO_HUBSPOT_TOKEN`, pipeline and stage ids), retries and operations.
- `signup-api.md` — the signup API `/sws/go/signup/v1` (ETP-5847) that creates a passwordless account and its demo environment from the marketing site's backend, a CRM or an agent: API keys (`ETGO_SIGNUP_API_KEYS`, hashes only), endpoints and error codes, the background provisioning, and the one-time login link (`POST /sws/go/session/link`).
- `agent-chat-api.md` — `/sws/agent-chat/*`: the history of the Etendo agent chat stored in the Copilot conversation tables, served to the Go cookie session (which `/sws/copilot/*` rejects). Route table, ownership rules, transaction handling, and the module-dependency note.
